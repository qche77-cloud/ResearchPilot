# 2026-10-14：当前代码审查与量化研究路线建议

审查对象：本地 `main`，提交 `3642d2c`。本轮读取实际实现、重跑离线测试并运行合成边界探针，没有修改生产代码、访问生产数据库、调用真实金融/模型 API 或执行交易。本文的新增功能均为建议，不能视为已实现。

## 结论

当前项目适合继续发展为“财务质量筛选 → Agent 核查原始证据 → 记录假设 → 持续检验”的研究工作台。已经具备确定性财务计算、研究状态与证据追溯基础，但尚无完整量化数据底座、因子股票池、历史回测和模拟组合。

下一步优先修复数据时点与质量边界，再开发小范围财务因子体检和筛选。策略回测依赖更完整的数据和执行规则；直接把报告文字或 LLM 判断转成历史买卖信号，无法证明策略有效。

## 按优先级列出的问题

### P1：开展量化前要补齐

**1. 财务的历史可用时点不完整。**

`src/financial_analysis.py:82` 的规范化检查财报期是否晚于获取日，但未全面验证 `published_at`。探针中获取时间为 2026-10-14、发布日期却为 2099-04-20 的记录仍为 `status=ok`。估值函数会挡住未公布财报，但其他财务计算及方向假设没有统一 as-of 入口。

`src/financial_analysis.py:395` 先选择报告期最新的分母，再在估值阶段检查发布日期。探针在 2026-02-01 有一份已公布的 2024 年报，按输入可算 PE=10；同时存在尚未公布的 2025 年报时，结果被 blocked，没有退回当时可用的 2024 年报。这没有输出前视估值，但不支持正确的历史估值选择。

`src/research_memory.py:9` 的财务快照字段未保留 `published_at`。原始输入另有保存，但报告内财务快照不能单独完整重建披露时点。

建议：保存报告期、披露时间、可用时间、采集时间和修订版本；所有研究/因子/估值统一使用 `as_of`，先筛选当时已公开且版本可核实的数据，再选择最新可用财报。历史原始文件没有可核实日期或存在无法追溯的后续重述时，只支持当前分析/前向观察，不冒充完整历史回放。

**2. 行情数据校验不足。**

`src/stock_data.py:51` 检查缺失值与非正价格，未检查有限数值、OHLC 高低关系及成交量非负。合成接口探针证明：最高价 2、最低价 12、开盘 10、收盘 11、成交量 -100 的记录可以返回；最高价 infinity 则通过检查，JSON 转换后变成 null。

建议：增加有限值、`low <= min(open, close) <= max(open, close) <= high`、成交量有效性、日期唯一性/排序和交易日历校验。缺日需区分停牌、非交易日与源缺失。错误记录隔离并报告质量原因，不能进入因子或回测。

**3. 多实例会覆盖状态。**

`src/background.py:28` 的 threads/lock 仅在一个进程内有效；`src/storage.py:193` 用整份 JSON UPSERT，没有 revision 比较。临时数据库探针中两个 Repository 读同一版本后各写一项，第二次写入丢失第一次修改。这是静态/受控写入证据，不是已完成生产并发压测。

建议：任务租约、worker ID、心跳与过期时间；研究状态使用 revision/CAS，命令消费及监控领取采用原子更新。先限制为单服务实例，再扩展批量研究，避免重复工具消耗和状态丢失。优先增加兼容的新表，不破坏旧历史。

**4. 引用完整性与结论支持必须分开衡量。**

`src/verifier.py:98` / `:110` 明确返回语义 unknown。探针中有效原文只是公司研发与销售的业务说明，却附在“具有显著技术护城河并长期领先”的结论后，完整性检查仍 passed。该行为符合目前狭窄验证契约，不能解释为语义已经被证明。

建议：把结论拆成原子 claim，关联证据片段、实体、时点、口径和反例；独立判定 supported / contradicted / insufficient，并要求判定也能引用片段。先建立人工标注的离线案例；模型评判作为可审计意见，不能单独视为事实认证。unknown 保持独立状态，不能换算为低风险或通过。

### P2：扩展规模与产品价值前加强

**5. 增加预算准入，而不仅记录费用。** `src/observability.py:123` 在请求结束后记录 usage/估算费用；搜索次数上限不是模型次数、输出 Token 或货币预算。建议限制每任务模型调用数、输出 Token、墙钟时间、并发和批次上限；未知费率时按调用/Token 上限降级控制。只有显式费率可估算金额，工具费独立记录。批量筛选全部用 Python，只有用户选中的少数异常公司才调用 Agent。

**6. 阅读器限制需要工程化。** `src/reader.py:309` 自动跟随重定向并读取完整 response.content；尚未见私网目标检查、逐跳验证和流式下载字节上限。建议允许协议与目标地址校验、重定向上限、下载/解析资源限制、原始文件哈希及来源类型分级；在读取来源或运行浏览器工具的实现中执行，不能只靠提示词。

**7. 通用假设与反思仍偏规则驱动。** `src/research_reasoning.py:94` 对没有金融 rule 的假设只绑定上下文来源；两条财务规则适合试点，但不能代表产业链、竞争优势或订单兑现都已自动检验。建议支持结构化判据、预期观测、反证条件和待验证日期，并在新来源出现时只更新对应命题。

**8. 可重复运行与检索性能。** 云端曾因 Streamlit 1.63/1.65 行为不同失败。建议维护已验收依赖约束和升级通道；当前只有 Windows/Python 3.11 CI，扩展平台按部署目标决定。Workbench 常用 symbol/time 查询可增索引；报告/轨迹作为大 JSON 增长后再按实际测量拆分，暂不强迁图数据库或 Agent 框架。

## 量化应该怎样接入

建议分为三个交付层，前两层直接强化现有研究价值：

| 层次 | 用户获得什么 | 依赖与边界 |
|---|---|---|
| 财务因子体检 | 公司收入、利润、现金兑现、利润率的多期面板；明确异常和缺失原因 | 最大限度复用当前计算模块；先补时间与质量校验 |
| 同业筛选与排序 | 对明确股票池做行业内比较，按增长/现金流/估值等规则筛选；逐条解释入选原因 | 需公司行业分类、批量标准数据、同期口径和缺失政策；评分与质量置信度分开 |
| 历史检验与模拟组合 | 验证筛选是否与未来经营兑现/收益相关，输出成本后表现和失败区间 | 需可回放数据、历史股票池、复权/公司行动、交易日历、成交与成本模型；不接实盘交易 |

### 第一版指标建议

1. **增长**：收入同比、归母利润同比；连续几期同比的稳定性。亏损转盈利、负基期单列，不用常规增长率混排。
2. **现金兑现**：同范围同期间经营现金流 TTM / 净利润 TTM。优先使用合并净利润与合并现金流；不能把归母利润与合并现金流的比例无说明地称为精确“利润含金量”。分母非正或数据缺失单列。
3. **经营质量**：毛利率/净利率的同比变化。毛利率要求营业成本，不能用营业总成本替代。财务与行业口径不同就停止比较。
4. **估值**：同一估值日 PE/PB 和同业分位。亏损、不明确市值单位、股本时间未知或缺少公开财报，返回不可比；不强行给正常 PE。
5. **风险体检**：增长与利润背离、利润与现金流背离、财务重述、数据陈旧与来源缺失。风险标志有来源，不能将没数据解释成没风险。

ROE、ROIC、应收周转、存货周转和杠杆率很有用，但当前标准字段不包含完整资产负债表与必要分母，应补充来源与口径后再加入。金融行业和一般工业公司分开设计，不套同一现金流分数。

首批选一个行业、20–50 家明确公司，展示原值、同业比较、数据覆盖率和证据链接。规模只是建议，不是已经下载的数据。规则/权重保存版本和参数；缺失项不补零，不把任意权重写成收益最优。样本不足时先展示原指标，不宣称同业分位稳定。

### Agent 在其中的职责

Python 计算指标与筛选 → Agent 获取入选/异常公司的原始公告 → 对解释寻找反例 → 输出带证据的研究 → 保存可验证判据与版本 → 新财报到来时检查兑现。

例如利润下降但收入增长，应由确定性指标触发研究；Agent 核查毛利率、费用、业务结构或一次性项目，不仅生成一段描述。每项解释标明证据支持范围和仍需核查的问题。量化信号、解释和人工判断分别保存。

## 后续回测必须满足的条件

- 因子值和股票池都按当时日期重建，包含退市、历史行业/ST 状态、上市时间和代码变更，避免仅用当前存活公司。
- 财务按披露/修订版本及可用时间加入；公告晚于决策时点不能使用。缺少具体披露时刻时采用明确的保守生效规则，不能默认报告期末就已知。
- 收益计算处理分红、拆股等公司行动；收益价格与真实成交价格分开，历史股本/市值使用当时数据。
- 收盘后产生的信号最早按下一可交易时点成交；处理 T+1、停牌、涨跌停、不同板块规则、整手与可成交量。不能无条件按理想价格成交。
- 佣金、最低手续费、滑点和税费是显式参数，并考虑历史规则变化；不是收益曲线画出来就算完成。
- 与同一股票池等权基准、适配的行业/市场基准比较，报告年化收益、波动、最大回撤、换手、暴露与交易明细；多空因子组合仅作为诊断时也须标明 A 股卖空限制。
- 因子诊断可包括分层收益、Rank IC 和跨期稳定性；经营兑现效果另行衡量，不用股价涨跌替代“财务假设正确”。
- 按时间分训练/验证/样本外区间；重叠未来收益标签有隔离窗口。保留失败参数实验，避免只展示事后调好的权重。
- 前向观察/模拟组合逐日记录真实可用输入和未成交原因。先验证研究流程，再讨论实际收益有效性；目前没有任何已验证策略收益。

## 除了量化，更值得做的三项

**公告/财报增量跟踪**：结构化记录公告类型、披露时刻、原始文件哈希与相关命题；新原文到来时只更新受影响研究。当前监控仅比较日线和财务源值，不等于公告订阅。

**研究兑现账本**：每项结论保存提出时间、具体判据、验证期限、反证条件和证据版本。后续分别检查经营事实是否兑现、观点是否修正、同期股价/基准表现。长期积累可复盘的研究样本，也能扩充真实 Agent 评测。

**研究质量面板**：原始来源比例、claim 语义支持/反例遗漏、日期/数值口径覆盖、关键问题覆盖、降级/失败原因、响应耗时、模型/工具预算和未知费用比例。分子分母公开；引用存在率不叫事实准确率。

## 推荐下一阶段范围与验收

建议 v2.1 先做“财务质量量化研究台”：先补日期/行情校验和相关回归，再增加有限行业股票池、因子原值、筛选原因和 Agent 深挖入口。保持旧工作台、自选与研究历史可用。

验收以真实可核对数据和确定性黄金值为准：每个值有来源/口径/时点；缺失与冲突阻止误排；同一天同一数据版本可重复算出相同结果；历史查询不使用后来公布的数据；Agent 解释须引用实际证据。没有完整历史底座时只交付当前筛选与前向验证，不把回测写成完成。
