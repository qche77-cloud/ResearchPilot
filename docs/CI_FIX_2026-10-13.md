## 根因与实际修复

Streamlit 的云端测试实现初始化 asyncio 事件循环。Windows 的 Python `socketpair` 回退实现使用临时回环 TCP 连接完成内部通信；原离线守卫替换所有 `socket.connect`，误拦截这条内部路径。当前本地 Streamlit 的测试实现没有同样的事件循环初始化路径，因此旧本地回归没有暴露问题。

修复位于 `scripts/run_offline_tests.py`：

- Windows 的 Python socketpair 回退改为使用调用内部创建的监听端和客户端；地址固定为 `127.0.0.1` / `::1`，端口由本次监听分配，仅在封闭调用中使用捕获的原连接方法。
- 不解除全局 connect/connect_ex/DNS 拦截，不允许一般回环地址访问，也不允许外部 API。原生 socketpair 平台不替换其实现。
- socketpair 两端恢复阻塞状态，失败时关闭已创建的套接字，设置初始化超时。
- 守卫初始化可重复调用，避免捕获已经被拦截的连接方法；保留生产 SQLite 访问阻断。
- 失败套件的诊断尾部直接输出到运行日志，避免以后只有 FAIL 标记而必须下载附件才能定位。

新增 `scripts/test_offline_guard.py` 的 6 个回归测试：内部数据往返、asyncio 循环初始化与执行、普通连接及 DNS 仍被阻断、Windows 参数边界、重复初始化和生产库隔离。已加入显式离线清单。

同时调整 `.github/workflows/offline-regression.yml`，只上传本次生成的 `offline-tests.json` 和 `agent-evaluation.json`，避免把仓库内历史成功报告混入当前失败运行的附件。
